# Foundation modes

Qeetrix keeps language, direction, density, color theme, motion preference, and viewport behavior
as separate concerns. Compose only the modes an application owns.

## Language and direction

`I18nProvider` supplies system-owned component strings and sets the document `lang` by default.
Set `setDocumentLanguage={false}` when the host already owns that attribute. Language does not
imply direction; compose `DirectionProvider` explicitly for RTL layouts.

```tsx
<I18nProvider locale="ar" messages={ar}>
  <DirectionProvider direction="rtl">{children}</DirectionProvider>
</I18nProvider>
```

Caller-owned content, option labels, and product terminology remain the caller's responsibility.

## Density

Density is opt-in so existing consumers retain their current dimensions. Use a subtree for a
preview or embedded tool, or apply the mode to the document at the app root.

```tsx
<DensityProvider density="compact" scope="document">
  {children}
</DensityProvider>
```

Default-sized controls, field rhythm, and table cells consume the generated density variables.
Explicit `xs`, `sm`, and `lg` sizes remain explicit overrides. Density never replaces mobile touch
guidance; use comfortable density for coarse-pointer primary workflows.

## Forced colors and focus

`styles.css` maps semantic colors to browser system colors under `forced-colors: active`. Focused
elements receive a token-driven `Highlight` outline even when shadows and custom rings are removed.
Do not disable `forced-color-adjust` on interactive controls without a tested reason.

## Responsive behavior

Use CSS first. `Container` provides the standard centered shell and responsive gutters. Tailwind's
default `sm`, `md`, `lg`, `xl`, and `2xl` ladder is canonical. `useMediaQuery`, `useIsMobile`, and
the exported query helpers are for behavioral adaptation only, such as switching a split view to a
modal detail panel.

## Token layers and enforcement

Primitive values feed semantic light/dark roles, stable component metrics, shared interaction
state, and data-visualization roles. `build-tokens` generates runtime CSS and typed values from the
same DTCG source; do not mirror motion, icon, stacking, shadow, or component constants by hand.

Use `--chart-1` through `--chart-8` for categorical identity and the dedicated grid, axis,
reference, positive, negative, and warning roles for chart structure and meaning. Run
`bun run tokens:scan` before review; exemptions are limited to documented domain data and
third-party selector shims.
