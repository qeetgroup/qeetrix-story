# Accessibility

Qeetrix targets **WCAG 2.1 AA** and **EN 301 549**, built on Base UI (WAI-ARIA APG
behaviour). Accessibility is enforced, not aspirational.

## What's guaranteed

- **Keyboard + ARIA** — interactive components inherit APG keyboard models, focus
  management, and roles/states from Base UI.
- **Contrast** — every required text/surface pair is held to AA by a token-level gate
  (`bun run tokens:validate`); the Qeet-orange brand pairs are enforced too.
- **Visible focus**, reduced-motion support, light/dark, and RTL throughout.

## Automated coverage

- `bun run --filter @qeetrix/ui test` runs Vitest + `vitest-axe`.
- `bun run --filter @qeetrix/ui test:a11y-coverage` is a **ratchet**: every component must
  have an automated a11y test, be in the smoke harness, or be on a shrinking exemption
  list. CI enforces it.

## For contributors

Run the per-component review in `docs/accessibility/audit-checklist.md` before shipping.
The conformance report template lives in `docs/accessibility/VPAT.md` (currently
self-reported, pending a third-party audit).

## Known caveat

`text.link` on white is currently ~3:1 with the orange brand — fine for large/UI text
but below the 4.5:1 body-text bar. Prefer `Button`/`Typography` link styling in dense
body copy until this is resolved (tracked in ADR 0004).
